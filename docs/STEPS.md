# 단계별 작업 지시문

한 번에 한 단계씩 진행합니다. 각 단계의 "지시문"을 Claude Code에 그대로 붙여 넣으면 됩니다.
단계가 끝나면 "확인할 것"을 직접 눌러 보고 다음 단계로 넘어갑니다.

## 모든 단계에 공통으로 적용할 규칙

- `docs/PLAN.md`의 정책과 `docs/DESIGN.md`의 디자인 기준을 따른다.
- 화면은 `docs/design/mobile/`의 해당 HTML과 같은 구조·수치로 만든다.
- 요청한 단계의 범위만 만든다. 다음 단계의 기능을 미리 만들지 않는다.
- Supabase 테이블을 만들 때는 반드시 RLS를 켜고 정책을 함께 작성한다.
- 비밀 키는 `.env.local`에만 두고 저장소에 올리지 않는다. `.env.example`에 이름만 적는다.
- 단계가 끝나면 (1) 만든 것 (2) 내가 직접 해야 할 일 (3) 확인 방법을 알려준다.

## 1단계. 프로젝트 세팅

**지시문**

```
docs 폴더의 문서를 읽고 1단계를 진행해줘.

- Next.js(App Router, TypeScript) + Tailwind CSS 프로젝트를 이 폴더에 만든다.
- docs/DESIGN.md의 색, 글꼴(GMarketSans 웹폰트 3종), 글자 크기 5단계, 버튼 규칙을
  Tailwind 설정과 전역 스타일에 토큰으로 넣는다.
- 공통 레이아웃을 만든다: 모바일 폭(최대 390~430px) 가운데 정렬, 바탕 #F5F5F4.
- 공통 컴포넌트를 만든다: 하단 탭(홈·검색·작성·마이), 칩, 주요 버튼, 가격 표시,
  사진 자리 표시, 구역(흰 바탕 섹션).
- docs/PLAN.md의 사이트맵대로 빈 페이지를 만들고 하단 탭으로 이동되게 한다.
- 홈(/)만 docs/design/mobile/D1Home.dc.html과 같게, 예시 데이터로 완성한다.
- README에 실행 방법을 적는다.
```

**확인할 것**: `npm run dev`로 실행해 홈이 디자인과 같은지, 글꼴이 GMarketSans로 보이는지, 하단 탭으로 페이지가 이동되는지

## 2단계. Supabase 테이블과 권한, 초기 데이터

**미리 할 일**: supabase.com에서 프로젝트를 만들고 프로젝트 URL과 anon key를 준비

**지시문**

```
2단계를 진행해줘.

- docs/PLAN.md 6번의 테이블을 만드는 SQL 마이그레이션 파일을 작성한다.
  (profiles, ingredients, recipes, recipe_ingredients, recipe_steps, saves, ingredient_substitutes)
- 모든 테이블에 RLS를 켜고 PLAN.md의 권한 원칙대로 정책을 작성한다.
- 닉네임은 대소문자를 무시한 고유 제약을 건다.
- 재료 가격이 바뀌면 그 재료를 쓰는 레시피의 price_per_serving을 다시 계산하는
  함수와 트리거를 만든다.
- 초기 데이터 SQL을 만든다: 자취 요리에 자주 쓰는 재료 30개(별칭, 단위, 예시 가격,
  기본 양념 여부), 대체 재료 10쌍, 예시 레시피 6개(재료와 단계 포함).
  가격은 예시 값이라는 주석을 단다.
- Supabase 클라이언트 설정(서버용/브라우저용)과 .env.example을 만든다.
- 내가 Supabase 화면에서 SQL을 실행하는 순서를 알려준다.
```

**확인할 것**: Supabase 화면에서 테이블 7개가 보이는지, 각 테이블에 RLS가 켜져 있는지, 예시 데이터가 들어갔는지

---

## 3단계. 레시피 목록과 상세

**지시문**

```
3단계를 진행해줘.

- /recipes: docs/design/mobile/D3Recipes.dc.html대로 만든다.
  가격·시간·도구 필터와 정렬이 실제 DB 조회에 반영되게 한다.
  필터 상태는 주소(쿼리)에 담는다.
- /recipes/[id]: docs/design/mobile/D4Detail.dc.html대로 만든다.
  1인분 단가, 장보기 비용, 재료별 금액, 기타 재료(단가 제외), 기본 양념, 조리 순서.
  저장 버튼은 모양만 만들고 동작은 5단계에서 붙인다.
- 홈의 인기·최신 레시피를 DB에서 가져오게 바꾼다.
- 두 페이지 모두 서버에서 렌더링하고, 상세 페이지에 제목·설명 메타 정보를 넣는다.
- 숨김 상태 레시피는 보이지 않게 한다.
```

**확인할 것**: 필터를 바꾸면 목록이 바뀌는지, 상세의 단가가 재료 금액 합과 맞는지

## 4단계. 재료 검색, 추천, 대체 재료

**지시문**

```
4단계를 진행해줘.

- 재료 자동완성: 이름과 별칭으로 찾는다 ("달걀"을 쳐도 "계란"이 나온다).
- /search: docs/design/mobile/D2Search.dc.html대로 만든다.
  선택한 재료 칩 추가·삭제, 주소는 /search?q=계란,양파 형태.
  기본 양념은 매칭에서 제외하고, 겹치는 재료가 많은 순으로 정렬한다.
  카드에 보유 현황 배지와 부족한 재료를 보여준다.
  대체 재료로 만들 수 있는 레시피는 아래에 따로 묶어 "A 대신 B로 가능"을 표시한다.
- 레시피 상세의 "대체" 버튼과 대체 재료 시트를
  docs/design/mobile/D5Substitute.dc.html대로 만든다. 차액은 이 레시피의 사용량 기준으로 계산한다.
- 홈 검색창과 바로가기를 /search, /recipes 필터로 연결한다.
- /ingredients/[name], /budget/[range] 페이지를 목록 화면과 같은 구성으로 만든다.
```

**확인할 것**: 재료를 넣고 빼면 결과와 순서가 바뀌는지, 별칭으로 검색되는지, 대체 시트의 차액이 맞는지

## 5단계. 로그인, 랜덤 닉네임, 저장

**미리 할 일**: 카카오·구글 개발자 화면에서 로그인 키를 만들고 Supabase 인증 설정에 등록 (방법은 Claude Code에 물어보면 안내받을 수 있음)

**지시문**

```
5단계를 진행해줘.

- /login: docs/design/mobile/D8Login.dc.html대로 만든다. Supabase 카카오·구글 로그인.
- 가입 시 profiles에 랜덤 닉네임("형용사+음식+숫자4자리")을 자동으로 만든다.
  겹치면 다시 뽑는다. 소셜 계정의 실명과 프로필 사진은 저장하지 않는다.
- 로그인이 필요한 동작을 비로그인으로 누르면 /login으로 보내고, 로그인 후 원래 페이지로 돌아온다.
- 레시피 저장·저장 취소를 붙인다.
- 카카오·구글 설정에서 내가 직접 해야 할 일을 순서대로 알려준다.
```

**확인할 것**: 로그인 후 닉네임이 자동으로 생기는지, 저장이 새로고침 후에도 유지되는지, 로그인 후 원래 페이지로 돌아오는지

**지시문**

```
6단계를 진행해줘.
```

**확인할 것**: 작성한 레시피가 목록·상세·검색에 나오는지, 다른 계정으로는 수정이 안 되는지

## 8단계. 관리자 페이지

**지시문**

```
8단계를 진행해줘.

- /admin 아래 페이지를 docs/design/admin/의 구성대로 만든다.
  색과 글꼴은 docs/DESIGN.md 기준으로 바꾼다. PC 화면 기준.

  내 계정을 admin으로 바꾸는 SQL을 알려준다.
- 요약: 레시피·재료·대체 재료 수, 처리할 기타 재료 수, 할 일 바로가기.
- 레시피 관리: 검색, 상태·작성자 필터, 수정, 숨김·공개, PC용 등록 양식,
  CSV 일괄 등록(미리보기 후 등록, 양식 파일 제공).
- 재료 가격표: 추가·수정, 별칭, 기본 양념, 갱신 30일 지난 재료 강조.
- 대체 재료: 쌍 추가·수정·삭제.
- 기타 재료 후보: 정식 재료로 등록, 기존 재료 별칭으로 연결, 무시.
  처리하면 해당 레시피의 단가를 다시 계산한다.
- "자취한끼 공식" 운영 계정으로 레시피를 올릴 수 있게 한다.
```

**확인할 것**: 일반 계정으로 /admin에 들어가면 막히는지, 재료 가격을 바꾸면 레시피 단가가 바뀌는지
